# E-Learning AI Hub

منصة تعليمية عربية تفاعلية تجمع بين أدوات الذكاء الاصطناعي، والتعلّم الصوتي، والمذاكرة الجماعية في تجربة واحدة. تستخدم المنصة نماذج **Google Gemini** لمساعدة المتعلم على طرح الأسئلة، شرح الدروس، إنشاء البطاقات التعليمية، تحويل المحتوى إلى صوت، وإنتاج بودكاست تعليمي.

واجهة التطبيق عربية بالكامل وتعمل باتجاه من اليمين إلى اليسار، مع دعم العربية الفصحى وعدة لهجات عربية في ميزات الصوت والمحادثة المباشرة.

## فكرة المشروع

يهدف **E-Learning AI Hub** إلى تحويل المحتوى التعليمي إلى تجربة تفاعلية قابلة للتخصيص. يستطيع الطالب استخدام مساعد ذكي لفهم موضوع معين، أو تحويل الدرس إلى شرح صوتي أو بودكاست، أو مراجعته عبر بطاقات تعليمية، أو دراسته مع زميل في جلسة جماعية.

يعتمد التطبيق على واجهة React/TypeScript وخادم Express. تمر معظم طلبات Gemini من خلال الخادم، بينما تستخدم المحادثة الصوتية المباشرة اتصال Gemini Live من الواجهة بعد الحصول على إعدادات الخدمة.

## الميزات التعليمية

### 1. المساعد الشخصي الذكي

- طرح الأسئلة العلمية والتعليمية باللغة العربية.
- إرسال السؤال إلى Gemini والحصول على إجابة نصية.
- عرض الإجابة داخل واجهة مخصصة للمحادثة.
- تحويل الإجابة إلى صوت عند الحاجة.
- اختيار صوت ذكر أو أنثى للاستماع إلى الإجابة.
- حفظ السؤال والنتيجة في سجل النشاط.
- مشاركة نتيجة المساعد مع شريك جلسة المذاكرة الجماعية عند وجود اتصال.

> تعرض بطاقة الميزة في الواجهة وصفًا يتحدث عن البحث الذكي في الويب. التنفيذ الحالي يستدعي Gemini مباشرة ولا يحتوي في الكود الحالي على موصل صريح لمحرك بحث خارجي؛ لذلك ينبغي اعتبار هذه العبارة وصفًا للاتجاه المقصود لا تكاملًا منفصلًا مثبتًا.

### 2. شرح الدروس

- إدخال اسم درس أو موضوع علمي.
- طلب شرح تفصيلي ومنظم من المساعد.
- توليد الشرح باللغة العربية.
- تحويل الشرح الناتج إلى صوت ذكر أو أنثى.
- حفظ الشرح في سجل النشاط.
- مزامنة نتيجة الشرح مع شريك جلسة المذاكرة الجماعية.

### 3. تحويل النص إلى صوت

- إدخال أي نص يرغب المستخدم في الاستماع إليه.
- تحويل النص إلى صوت باستخدام Gemini.
- اختيار صوت ذكر أو أنثى:
  - صوت الذكر الافتراضي: `Puck`
  - صوت الأنثى الافتراضي: `Kore`
- تطبيق اللهجة المختارة على النص الصوتي.
- تشغيل الصوت الناتج داخل التطبيق.
- حفظ العملية في سجل النشاط.

### 4. إنشاء بودكاست تعليمي

- لصق محتوى درس أو مقال.
- تحويل المحتوى إلى حوار تعليمي يحافظ على أفكار النص.
- اختيار نوع الحوار:
  - سؤال وجواب
  - نقاش طبيعي
  - نقاش حاد
- استخدام معرفين للمتحدثين في السيناريو:
  - `EXPERT` للخبير
  - `LEARNER` للمتعلم
- تحويل السيناريو الناتج إلى صوت.
- الاستماع إلى البودكاست داخل التطبيق.
- حفظ النص الصوتي والسيناريو في سجل النشاط.
- مزامنة نتيجة البودكاست مع شريك الجلسة الجماعية.

> تستخدم النسخة الحالية مسار تحويل صوت واحدًا للصوت الناتج، رغم أن السيناريو يميز بين الخبير والمتعلم. يمكن تطويرها لاحقًا لإسناد صوت مستقل لكل متحدث.

### 5. إنشاء البطاقات التعليمية

- إدخال نص درس أو محتوى تعليمي.
- تحديد عدد البطاقات المطلوب إنشاؤها.
- استخراج المصطلحات المهمة باستخدام Gemini.
- إنشاء كل بطاقة بصيغة:
  - المصطلح `term`
  - التعريف `definition`
- عرض البطاقات للمراجعة.
- حفظ البطاقات في سجل النشاط.
- مزامنة البطاقات مع شريك جلسة المذاكرة الجماعية.

### 6. محلل الملفات الذكي

- رفع ملف من واجهة التطبيق.
- رفض الملفات التي يزيد حجمها عن **4 ميجابايت** لضمان سرعة المزامنة.
- حفظ بيانات الملف بصيغة Base64 داخل حالة التطبيق.
- تسجيل اسم الملف ونوع MIME الخاص به.
- إدخال سؤال عن محتوى الملف.
- إجراء محادثة نصية متتابعة حول الملف.
- حفظ سجل الأسئلة والإجابات المرتبطة بالملف.
- تحويل إجابات التحليل إلى صوت ذكر أو أنثى.
- فتح محادثة صوتية مباشرة مخصصة للملف.
- مزامنة الملف وسجل الحوار والنتيجة مع شريك الجلسة الجماعية.
- حفظ عملية تحليل الملف في سجل النشاط.

> **حالة التنفيذ الحالية:** الواجهة تجمع بيانات الملف وترسلها ضمن حالة التطبيق، لكن الدالة الحالية `analyzeFileChat` في `geminiService.ts` لا تمرر محتوى الملف فعليًا إلى نقطة Gemini في الخادم؛ إذ تُرسل حاليًا مطالبة نصية تتضمن اسم الملف والسؤال. لذلك فإن ربط التحليل بمحتوى الملف الفعلي يحتاج إلى استكمال في الخادم قبل الاعتماد عليه كتحليل كامل للملفات.

## المحادثة الصوتية المباشرة

### 7. Gemini Live

- بدء جلسة صوتية مباشرة مع المساعد.
- التقاط صوت المستخدم من الميكروفون.
- إرسال الصوت واستقبال الردود الصوتية لحظيًا.
- عرض حالة واضحة أثناء استماع المساعد.
- إيقاف الجلسة يدويًا.
- استخدام اللهجة المختارة من إعدادات المنصة.
- دعم تعليمات مخصصة عند تشغيل المحادثة حول ملف مرفق.
- إظهار مؤشر مرئي لحالة البث المباشر.
- احتساب مدة الاستخدام الصوتي ضمن الحد اليومي.

يستخدم الاتصال نموذج `gemini-2.0-flash` وإعداد الصوت `Zephyr` في مسار Gemini Live الحالي.

## المذاكرة الجماعية

### 8. إنشاء جلسة دراسة

- إنشاء جلسة جديدة من قسم المذاكرة الجماعية.
- إنشاء معرف اتصال PeerJS عشوائي مسبوقًا بـ `elearn-`.
- الحصول على كود جلسة قصير قابل للمشاركة.
- نسخ كود الجلسة إلى الحافظة.
- نسخ رابط التطبيق لإرساله إلى الزميل.
- عرض حالة انتظار انضمام الشريك.

### 9. الانضمام إلى جلسة

- إدخال كود الجلسة.
- الاتصال بالجلسة عبر PeerJS.
- عرض حالة الاتصال بعد نجاح الانضمام.
- إنهاء الجلسة وإعادة ضبط الحالة عند الحاجة.

### 10. مشاركة المحتوى والمزامنة

عند اتصال مستخدمين في الجلسة، يمكن مزامنة العناصر التالية بينهما:

- إجابات المساعد الشخصي.
- شروحات الدروس.
- نتائج تحليل الملفات.
- الملف المرفق وسجل الأسئلة المرتبطة به.
- البطاقات التعليمية.
- سيناريو البودكاست ونتيجته الصوتية.
- الرسائل النصية.

تظهر نتائج المزامنة مباشرة لدى الطرف الآخر حسب القسم النشط.

### 11. الدردشة النصية

- إرسال رسالة إلى شريك الجلسة.
- عرض الرسائل المرسلة والمستلمة.
- حفظ وقت كل رسالة.
- فتح واجهة الدردشة تلقائيًا عند وصول رسالة جديدة.

### 12. المكالمات الصوتية الجماعية الثنائية

- بدء مكالمة صوتية مع شريك الجلسة.
- استقبال مكالمة واردة.
- قبول المكالمة أو رفضها.
- إنهاء المكالمة.
- كتم الميكروفون وإلغاء الكتم.
- عرض حالات الاتصال: خاملة، جارٍ الاتصال، مكالمة واردة، متصلة.
- تشغيل الصوت البعيد عبر عنصر صوت في المتصفح.
- استخدام PeerJS وWebRTC للوصول إلى الميكروفون ونقل الصوت.

## الحسابات وإدارة الاستخدام

### 13. تسجيل الدخول عبر Google

- تسجيل الدخول باستخدام Firebase Authentication وGoogle Popup.
- عرض اسم المستخدم والبريد الإلكتروني والصورة الشخصية.
- فتح قائمة المستخدم من الهيدر.
- تسجيل الخروج.
- التعامل مع خطأ الدومين غير المصرح به في Firebase.
- عرض إرشادات عند الحاجة إلى إضافة دومين المعاينة إلى Firebase.

### 14. الدخول كزائر

- استخدام المنصة دون تسجيل حساب Google.
- إنشاء معرف زائر مؤقت بصيغة `guest_...`.
- حفظ بيانات الزائر في `localStorage`.
- استعادة جلسة الزائر عند إعادة تحميل الصفحة على نفس المتصفح.
- جلب إحصاءات الاستخدام الخاصة بالزائر.
- إمكانية تسجيل الخروج ومسح بيانات الزائر المحلية.

### 15. حدود الاستخدام اليومية

يطبق الخادم حدودًا افتراضية لكل مستخدم:

- **10 رسائل يوميًا.**
- **300 ثانية صوت يوميًا**، أي 5 دقائق.

تتضمن إدارة الاستخدام:

- عرض عدد الرسائل المستخدمة من أصل 10.
- عرض مدة الصوت المستخدمة من أصل 5 دقائق.
- عرض أشرطة تقدم مرئية في قائمة المستخدم.
- رفض الطلب عند تجاوز الحد برسالة واضحة.
- إعادة ضبط الاستخدام عند تغير التاريخ.
- تخزين الإحصاءات في مجموعة `usage` داخل Firestore عند توفره.
- استخدام مخزن داخل الذاكرة كحل بديل عند تعذر الوصول إلى Firestore.

تستهلك الرسائل عادةً وحدة واحدة، بينما تُحسب العمليات الصوتية بحسب المدة المقدرة أو المدة المستخدمة.

## سجل النشاط

### 16. حفظ العمليات واستعادتها

يحتفظ التطبيق بسجل محلي للعمليات التي ينفذها المستخدم، ومنها:

- المساعد الشخصي.

- شرح الدروس.

> السجل الحالي محفوظ في حالة الواجهة ولا يمثل نظام أرشفة دائمًا في قاعدة البيانات.

## الخدمات والـ API

يوفر `server.ts` خادم Express على المنفذ `3000`، ويتضمن المسارات التالية:

| المسار | الطريقة | الوظيفة |
| --- | --- | --- |
| `/api/health` | `GET` | فحص صحة الخادم وإرجاع الحالة `ok`. |
| `/api/config` | `GET` | إرجاع مفتاح Gemini المتاح للاتصال المباشر من الواجهة. |
| `/api/ai/assistant` | `POST` | إرسال مطالبة إلى Gemini وإرجاع الإجابة النصية. |
| `/api/ai/tts` | `POST` | توليد صوت من نص مع صوت ولهجة محددين. |
| `/api/ai/flashcards` | `POST` | استخراج بطاقات تعليمية بصيغة JSON. |
| `/api/usage` | `POST` | جلب استخدام المستخدم لليوم الحالي. |
| `/api/usage/update` | `POST` | تحديث عداد الرسائل أو الثواني الصوتية. |
| `/api/export` | `GET` | تنزيل ملفات المشروع في أرشيف ZIP. |

كما يهيئ الخادم Socket.IO ويحتوي على أحداث غرف مثل إنشاء الغرفة والانضمام إليها ومزامنة بعض البيانات. يعتمد مسار المذاكرة الجماعية الحالي في الواجهة بصورة أساسية على PeerJS للاتصال المباشر.

## إعداد متغيرات البيئة

انسخ `.env.example` إلى `.env` وأضف مفتاح Gemini:

```env
GEMINI_API_KEY=your_gemini_api_key
```

يدعم الخادم أيضًا أسماء المتغيرات البديلة التالية:

```env
VITE_GEMINI_API_KEY=your_gemini_api_key
VITE_GEMINI_API_KEY_1=your_gemini_api_key
GEMINI_API_KEY_1=your_gemini_api_key
```

لا تضع ملف `.env` أو أي مفاتيح سرية في Git. ملف `.env.example` مخصص للتوضيح فقط.

## التشغيل محليًا

1. استنسخ المستودع:

   ```bash
   git clone https://github.com/hhuuhgf5-png/AI.git
   cd AI
   ```

2. ثبّت الاعتماديات:

   ```bash
   npm install
   ```

   أو استخدم مدير الحزم المتوافق مع ملف `bun.lock`.

3. أنشئ ملف `.env` وأضف مفتاح Gemini.

4. شغّل بيئة التطوير:

   ```bash
   npm run dev
   ```

5. افتح التطبيق على:


## أوامر المشروع

| الأمر | الوصف |
| --- | --- |
| `npm run dev` | تشغيل الخادم وواجهة Vite في وضع التطوير. |
| `npm run build` | بناء واجهة Vite وتجميع `server.ts` داخل `dist/server.cjs`. |
| `npm start` | تشغيل الخادم المبني من `dist/server.cjs`. |
| `npm run lint` | فحص TypeScript باستخدام `tsc --noEmit`. |

## ملاحظات مهمة وحالة الميزات

- الحد اليومي للرسائل والصوت مضبوط حاليًا في الخادم على 10 رسائل و300 ثانية صوت لكل مستخدم.
- التخزين البديل داخل الذاكرة يفقد البيانات عند إعادة تشغيل الخادم؛ التخزين الدائم يتطلب إعداد Firestore.
- يحتاج تسجيل الدخول عبر Google إلى إضافة الدومين المستخدم إلى قائمة Firebase Authorized Domains.
- استخدام الميكروفون يتطلب موافقة المستخدم واتصالًا آمنًا في البيئات المنشورة.
- حجم الملف في واجهة محلل الملفات محدود بـ 4 ميجابايت.
- تحليل محتوى الملفات فعليًا يحتاج إلى استكمال تمرير بيانات الملف من `geminiService.ts` إلى خادم Gemini.
- سجل النشاط محفوظ في حالة React الحالية ولا يستمر تلقائيًا بين الجلسات.
- الصوت متعدد المتحدثين في البودكاست يستخدم حاليًا مسار صوت واحد؛ يمكن تحسينه لاحقًا بصوت مستقل لكل شخصية.
- واجهة البحث الذكي موجودة في وصف بطاقة المساعد، لكن لا يوجد حاليًا تكامل منفصل مع محرك بحث خارجي في الكود.
- لا يوجد ترخيص مفتوح المصدر محدد للمشروع حتى الآن.

لم يُحدّد ترخيص مفتوح المصدر للمشروع بعد.
